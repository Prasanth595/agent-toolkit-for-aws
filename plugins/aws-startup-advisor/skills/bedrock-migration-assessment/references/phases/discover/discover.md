# Discover AI workloads

Before selecting or writing any Discover output, invoke `scripts/bma-runtime.py execute --request -` with the current state, mode, scenario, provider consent outcomes, and the complete planned write set. Use its returned state decision and exact writer/audit rows; it prevalidates every path, owner, payload, contribution, and existing-target rule before rollback-safe publication, so a rejected request leaves the run/state tree unchanged. Every enrichment of an existing AI profile, provider profile, capture manifest, preview, or state/checkpoint includes `expected_sha256` for the exact prior bytes; delegated GCP Vertex seeding is followed only by a BMA-owned profile enrichment with that prior hash. Unknown paths and owners are rejected. This is the production state, consent, writer, and physical-write boundary, not an advisory check.

Run `references/phases/discover/discover-app-code.md`, then consent-gated provider discovery in this order: `references/phases/discover/discover-openai-api.md`, `references/phases/discover/discover-openrouter-api.md`, `references/phases/discover/discover-anthropic-api.md`, then `references/phases/discover/discover-preview.md`. Source-containing input is scanned once; confidence below 70% writes no AI profile.
